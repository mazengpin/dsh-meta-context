`GET /meta-context/api/bundle` is the meta bundle census. For each of the nine `dsh-meta-*` packages the bundle declares a route-family root, one row reports whether the package directory exists under `plugins-src/`, the `name`, `version` and `dsh`/`cordis` entry read from that directory's `package.json`, and the HTTP status received when the family root and its `/api` subpath are probed on the same server that served the request, addressed by the request's own `Host` authority. Three states are kept apart and none is a zero: an absent package is `present: false`; a package that is present but answered no 200 is `mounted: false` explicitly, with the status and the reason; and anything that was not probed carries `status: null` with the reason, because no server answers `0` and a `0` here would be a number this code invented. The census writes nothing — every read is a directory listing, a `package.json` read and an outbound `GET`, with no change to any package directory, manifest, route table or profile.

## Why this exists in the ecosystem

The DSH plugin ecosystem is messy because every plugin invents its own route, its own panel and its own vocabulary. A package aligned to the intent map declares what it does in one place, which makes it discoverable, stable across upgrades and reviewable by a stranger. This package is one such declaration: one census route, one typed contract and one stated falsifier, so what it publishes can be checked rather than taken on its word.
